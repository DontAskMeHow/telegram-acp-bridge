# telegram-acp-bridge

Управление ИИ-агентом кодинга (Kimi, `kimi acp`) с телефона через Telegram.
Один чат Telegram = одна сессия агента: процесс агента стартует лениво по
первому сообщению, час простоя держится тёплым, затем глушится; контекст
живёт на диске и поднимается для следующего сообщения. Живой прогресс
(размышления, вызовы инструментов, ответ) перерисовывается в редактируемом
сообщении чата, запросы разрешений приходят инлайн-кнопками, к задаче можно
прикрепить фото.

## Архитектура

- **Лонг-поллинг-бот на aiogram 3** — демон; публичный IP и вебхук не нужны.
- **Собственный ACP-клиент** (`kimi_acp.py`) — Agent Client Protocol,
  JSON-RPC 2.0 поверх stdio. Один процесс `kimi acp` обслуживает несколько
  сессий — по одной на чат; поток-читатель делит stdout на фьючерсы ответов,
  события `session/update` и серверные запросы `session/request_permission`.
- **Ленивый жизненный цикл агента** — процесс поднимается по требованию,
  после простоя `acp_idle_sec` (по умолчанию 3600 с) паркуется, сессии
  восстанавливаются через `session/load` (повтор истории вычитывается, в чат
  не показывается).
- **Сетевой watchdog** — периодическая проба достижимости `api.telegram.org`;
  при сбое мост уходит на прокси (конфиг `proxy` или `PROXY` / `HTTPS_PROXY`)
  и обратно, перепривязывая сессию бота без потери поставленных в очередь
  сообщений. При старте без сети — повторы каждые `net_retry_sec`.

## Структура

```
scripts/tg_bridge.py   демон + CLI (start/stop/status/log/install/uninstall)
scripts/kimi_acp.py    ACP-клиент (JSON-RPC 2.0 поверх stdio)
scripts/tg_net.py      проверка достижимости Telegram, фолбэк на прокси, конфиг
scripts/acp_probe.py   самопроверка: реальный хендшейк, промпт, поток разрешений
tg.local.example.json  шаблон конфигурации (скопировать в tg.local.json)
```

## Быстрый старт

1. `pip install -r requirements.txt` (проверено на Python 3.12+, aiogram 3.31).
2. Создайте конфиг: `cp tg.local.example.json tg.local.json` и заполните:
   - `bot_token` — от @BotFather (обязателен; без него мост завершается с
     понятной ошибкой),
   - `allowed_user_ids` — ваш Telegram user id (или несколько); **пустой
     список = владельцем становится первый написавший боту**,
   - `workspace` — каталог, в котором работает агент (по умолчанию: каталог
     репозитория),
   - `kimi_bin` — путь к бинарю агента (по умолчанию: `kimi` из PATH или
     переменная `KIMI_BIN`),
   - `proxy` — URL SOCKS/HTTP-прокси, опционально (также env
     `PROXY`/`HTTPS_PROXY`).
3. Прогоните самопроверку (без участия Telegram): `python scripts/acp_probe.py`.
4. Запустите мост: `python scripts/tg_bridge.py start`
   (на Windows `python scripts/tg_bridge.py install` дополнительно
   регистрирует задачу Планировщика при входе; `stop` / `status` / `log` —
   управление).
5. Откройте бота в Telegram и отправьте `/start`.

Состояние, логи и pid-файл лежат в `data/` (в gitignore) рядом с конфигом.
Конфиг содержит токен — не храните его в системе контроля версий.
